# Novel Reader — IDEA 在线小说阅读插件

按**自定义 JSON 规则**在线解析小说目录与章节正文，可输出到 IDEA 的 **Notifications 通知**
或右侧**阅读面板**，并自动记录阅读历史、支持书签标记，方便在工作间隙逐段阅读。

## 功能特性

- **安装即用**：自带天籁小说网默认规则，装完直接粘 URL 就能读，无需手工配置
- 粘贴小说【目录页 URL】即可解析出**完整章节目录**，选择起始章节开始阅读
- 正文在 IDEA Notifications 中逐段展示，通知里**只显示小说内容**
  （不含章节名、段号，也不带翻页按钮），可设置**每段最大字数**
- **专用阅读面板（可选）**：IDE 右侧的 ToolWindow 里**一次显示整章正文**，可自由滚动、
  可选中复制；**字号与行距可随时调**（面板按钮或设置页），并有一行状态提示
  （正在加载 / 加载失败 / 到头了）。
  与通知模式**并存**，由设置项「渲染方式」切换（默认仍是通知，老用户升级无感）
- **读完本章自动加载下一章**，连续阅读不断档
- **章节目录**对话框：顶部筛选框可搜章节名或序号；**打开时自动定位到当前正在读的章节**
  （选中并滚动到可见区域，该行还标着「← 当前」），不用每次从第 1 章往下翻
- **阅读历史**：每次翻页自动记录进度（精确到**章 + 段**），**关掉 IDEA 再打开依然在**；
  弹窗列出读过的书（含上次读到哪一章哪一段与阅读时间），点一下即回到原处，也可逐条删除
- **书签**：随手把当前段标记下来（可附一句备注，自动带一段正文摘录），
  在一本书内**任意跳回**；与「历史只有一条」互补，一本书可以有很多条
- **离线缓存**：读过的章节自动存到本地，**再读不再发请求**；
  「缓存整本书」可提前把整本下下来，之后**断网或站点打不开也能继续阅读**
  （连目录页都做了缓存，所以离线时还能从「阅读历史」恢复）
- 全部操作收在 `Tools → Novel Reader` **二级子菜单**里，菜单 / 快捷键翻页与按章翻阅
- **图形化规则编辑**：设置页「编辑规则…」可增删改规则、调整各字段（含选择器、剔除列表、请求头），
  保存前**自动备份**原文件为 `rules.json.bak`
- 规则以**本地 JSON** 存储，可随时编辑并「重新加载」
- 支持一章分多页的站点：自动定位「下一页」并拼接为完整章节
- 自动处理 **GBK / GB2312 编码**与 **gzip 压缩**响应

## 构建与运行

```bash
# 编译 + 单元测试
./gradlew test

# 打包插件（产物在 build/distributions/novel-reader-1.0.0.zip）
./gradlew buildPlugin

# 直接启动一个带插件的 IDEA 实例做联调
./gradlew runIde
```

> 构建脚本默认使用本机安装的 IDEA 作为目标平台（`build.gradle.kts` 中的 `local("D:/java/idea")`）。
> 换机器时把该路径改成自己的 IDEA 安装目录，或改为 `intellijIdea("2026.1")` 让 Gradle 自动下载平台。
>
> `gradle/wrapper/gradle-wrapper.properties` 的发行版地址指向腾讯云镜像（部分网络环境下
> `services.gradle.org` 会重定向到 GitHub，可能不可达）。网络正常时可改回
> `https://services.gradle.org/distributions/gradle-9.7.1-bin.zip`。

### 安装到 IDEA

`Settings / Preferences → Plugins → ⚙ → Install Plugin from Disk...`，选择
`build/distributions/novel-reader-1.0.0.zip`，重启后生效。

## 使用说明

所有功能都收在 **`Tools → Novel Reader`** 一个二级子菜单下，Tools 根菜单不再散落多条目。

1. 打开 `Tools → Novel Reader` 菜单 → **打开：粘贴目录URL阅读**（默认快捷键 `Ctrl+Alt+N`）。
2. 粘贴小说的**目录页** URL（不是章节页，也不是首页），回车。
3. 插件按域名匹配规则，解析出**完整章节目录**，并询问起始章节（直接回车从第 1 章开始）。
4. 正文以通知形式输出。通知里**只有小说内容**：正文被放进通知的标题栏并压小了字号，
   内容栏留空，也不挂任何按钮。通知默认不弹窗，内容写入 Notifications 面板。
5. 翻页（通知内没有翻页按钮，请用菜单或快捷键）：

   | 菜单项 | 快捷键 | 说明 |
   | --- | --- | --- |
   | 下一页 | `Ctrl+Alt+.` | 下一段；**本章读完自动加载下一章** |
   | 上一页 | `Ctrl+Alt+,` | 上一段；本章开头时回到上一章**最后一段** |
   | 下一章 | `Ctrl+Alt+Shift+.` | 直接跳到下一章开头 |
   | 上一章 | `Ctrl+Alt+Shift+,` | 直接回到上一章开头 |
   | 章节目录 | `Ctrl+Alt+Shift+L` | 打开对话框，**默认选中并滚到当前章**；输入章节名或序号筛选，回车（或双击）跳转 |
   | 添加书签 | `Ctrl+Alt+Shift+M` | 把当前段存为书签，可写一句备注（`M` = Mark） |
   | 书签列表 | `Ctrl+Alt+Shift+B` | 查看**当前这本书**的书签，选中后跳转，可删除选中或全部 |
   | 缓存整本书 | `Ctrl+Alt+Shift+D` | 把当前这本书整本抓到本地（后台进行、可取消），之后断网也能读 |
   | 阅读历史 | `Ctrl+Alt+H` | 列出读过的书与上次读到的章/段，**选中后点「继续阅读」**，可删除选中或全部 |
   | 关闭阅读 | `Ctrl+Alt+Shift+Q` | 结束阅读会话并清掉正文通知 |

> 快捷方式可在 `Settings → Keymap → Plug-ins → Novel Reader` 中自行修改。
> 书签的 `Ctrl+Alt+Shift+M` / `B` 与缓存的 `Ctrl+Alt+Shift+D` 都刻意带 `Shift`：
> `Ctrl+Alt+B` 与 `Ctrl+Alt+M` 在 IDEA 默认键位表里分别是「跳转到实现」「提取方法」，
> 属于高频键，不去抢占。

### 阅读历史

**每次正文渲染时自动记录**当前书、章、段及时间——因此翻页、跳章、目录跳转、从历史恢复，
所有路径都会被记上，无需手动保存。

- **持久化**：写入 `{IDEA 配置目录}/novelReader/history.json`，
  **关闭并重开 IDEA 后仍然存在**。最多保留 **50 本**（按最近阅读排序，超出丢弃最旧的）。
- **打开**：`Tools → Novel Reader → 阅读历史`（`Ctrl+Alt+H`）。列表按最近阅读倒序，
  文案形如 `书名 · 第 12 章 风起 · 第 3 段`，并附带相对时间（如「3 分钟前」）。
- **继续阅读**：先在列表里**选中**一本书，再点「继续阅读」（或**双击**该行）→ 后台
  **重新解析目录**并定位到上次的章与段，正文以通知输出。
- **删除**：选中一条或多条（`Ctrl` / `Shift` 多选）后点**「删除选中」**；
  点**「删除全部」**会二次确认后清空整个历史。删除立即落盘。
- **按钮都在同一行**：`继续阅读` · `删除选中` · `删除全部` · `取消`。四个按钮都由
  `DialogWrapper.createActions()` 返回，由平台统一布局在按钮行里，
  不会出现「一行列表按钮 + 一行确定取消」的割裂感。
- **为什么不做「行尾 ×」**：曾经在每行右侧画一个 `×` 按钮，结果**点删除反而进入阅读**——
  弹出式列表把「整行被点击」统一当成「选中并立即回调」，行内按钮的点击也落在同一个
  回调上，两者无法区分。现在改用对话框：**列表只负责选择，所有动作都由按钮显式触发**，
  这类误触在结构上就不可能发生了。删除后选择会被清空，避免紧接着回车打开一本没打算看的书。
- **定位策略是「URL 优先、下标兜底」**：优先用上次记录的**章节 URL** 在本次解析出的目录里
  找同一章（站点增删章节后下标会漂移，URL 才可靠）；找不到 URL 时才退回用下标，并夹取到合法范围。
  段号越界时退到**最后一段**而不是第 1 段，避免进度看起来倒退了。
- **历史坏了不影响插件**：文件缺失、内容损坏、路径不可写、读取抛异常，一律退化为「空历史」
  或静默忽略，绝不会导致插件启动失败。文件同样支持 `//` 注释与尾随逗号，可手工编辑。

> 单章模式（无目录）不记录历史——它没有稳定的书标识。每本书以**目录页 URL** 唯一标识，
> 重复打开同一本书只会更新进度并顶到列表最前，不会产生重复条目。

### 书签

历史回答的是「我上次读到哪」，书签回答的是「我想回头看哪一段」——
所以历史每本书**只有一条**（自动写），书签一本书**可以有很多条**（手动加）。

- **添加**：读到想标记的地方，按 `Ctrl+Alt+Shift+M`（或面板工具栏「书签」→「添加当前位置」），
  会弹一个输入框让你写备注，**可以留空**。留空时书签名字就是章节位置。
  每条书签会自动带上**当时那一段的开头摘录**，这样同章内的几条书签在列表里一眼能分开。
- **跳回**：`Ctrl+Alt+Shift+B` 打开书签窗口 —— 列表按**阅读顺序**（章 → 段）排列，
  选中一条点「跳转」（或双击）即回到那个位置。目标就是当前章时**只移动游标、不重新请求**。
- **删除**：`删除选中`（可 `Ctrl` / `Shift` 多选）与 `删除全部`（二次确认）。
  「删除全部」只删**当前这本书**的书签，不会连累别的书。
- **按钮都在同一行**：`跳转` · `添加当前位置` · `删除选中` · `删除全部` · `取消`，
  同样全部由 `DialogWrapper.createActions()` 返回。列表只负责选择，副作用全由按钮触发。
- **持久化**：`{IDEA 配置目录}/novelReader/bookmarks.json`，与历史同级，最多 **200** 条。
  容错策略与历史一致（损坏 / 不可写一律退化为空或静默忽略，绝不打断阅读），
  同样支持 `//` 注释与尾随逗号，可手工编辑。
- **同一位置只留一条**：在同一个地方再按一次「添加书签」不会新增条目，而是**更新那一条**
  （备注非空才覆盖，避免重复添加时清掉已写好的备注）。
- **位置只按书区分**：书签窗口只显示**当前打开的那本书**的书签。跨书回到某本书这件事
  由「阅读历史」负责（书签的定位依赖当前会话已解析出的目录，这样跳转不需要网络请求）。
- **单章模式不能加书签**：它没有目录页 URL，重启后无法定位回来 —— 存了也只会变成一个
  跳不过去的死条目，所以直接拒绝并说明原因。

### 离线缓存

**默认开启**（`Settings → Tools → Novel Reader → 离线缓存`）。两件事一起解决：
已读过的章节再读一遍不必重新请求；断网或站点挂掉时还能继续读。

- **自动缓存**：每次成功抓取一章就会存到本地。所以「读过的」= 「已缓存的」。
- **提前下载**：`Tools → Novel Reader → 缓存整本书`（`Ctrl+Alt+Shift+D`）
  把整本抓到本地 —— 后台进行，进度条显示「第 N / M 章」，随时可取消；
  **已有缓存的章节直接跳过**，结束时会汇报「新缓存 N 章 / 跳过 M 章 / K 章失败」。
- **读取策略是「缓存优先」**：命中缓存就**直接返回、完全不发请求**。
  章节正文是静态内容，重复请求纯属浪费；而且「网络优先」在离线时得先等超时与重试
  （默认 3 次）才轮到缓存，读一章要等十几秒，那不叫离线阅读。
  想拿最新内容时，用设置页的**「清空缓存」**。
- **目录也缓存**：只缓存正文是不够的 —— 从「阅读历史」恢复时会**重新解析目录页**，
  没网时这一步就失败，缓存再多正文也进不去。所以每本书还存了一份目录快照
  （`book.json`），目录页打不开时直接用它把会话建起来，并提示「已改用离线缓存的目录」。
- **离线找不到上次那章会就近退让**：历史记的那一章若刚好没缓存，会跳到**最近的已缓存章节**
  并说明，而不是让整本书都打不开。
- **与「每段最大字数」联动**：缓存里记着写入时的切分参数，用户改过设置后旧缓存会被视为
  未命中并重新抓取 —— 避免同一本书里新老章节的段落划分不一致。
- **存放在** `{IDEA 配置目录}/novelReader/cache/<书的摘要>/`：一本书一个目录，
  一章一个 `c-<章节摘要>.json`（**不是**所有章节塞一个文件 —— 那样每读一章都要重写几 MB）。
  设置页的「清空缓存」会显示占用大小并二次确认；**清缓存不影响阅读历史与书签**。
- **缓存坏了不影响阅读**：文件缺失 / 损坏 / 不可写一律退化为「未命中」去联网，静默忽略写入失败。
  文件支持 `//` 注释与尾随逗号，可手工编辑。

## 规则配置

### 规则文件位置

默认：`{IDEA 配置目录}/novelReader/rules.json`，例如
`C:\Users\<你>\AppData\Roaming\JetBrains\IntelliJIdea2026.1\novelReader\rules.json`。

可在 `Settings → Tools → Novel Reader` 中修改路径，或用该页的
**打开规则文件** / **编辑规则…** / **重新加载规则** 按钮操作。

### 图形化编辑规则

设置页点 **「编辑规则…」**：

- 上半部分是**规则表格**（一行一条规则）：启用 / 规则名 / 匹配方式 / 匹配内容 / 编码 / User-Agent，
  适合横向对比多条规则；下方按钮可**新增 / 复制 / 删除 / 上移 / 下移**（顺序影响命中优先级）。
- 下半部分是选中规则的**全字段表单**：各种选择器、示例 URL、要剔除的节点、分页设置、额外请求头。
  表单底部会实时提示这条规则「可能的问题」（缺 `siteMatch.pattern`、缺 `linkSelector`、
  字符集名写错等），但**只提示不拦着**，你仍然可以保存。
- **改动在点「保存」时才写回文件**，点「取消」什么都不变（编辑的是一份副本）。

> ⚠️ **保存会重写整个文件**，你手写的 `//` 注释与排版会丢失。
> 因此保存前会自动把原文件备份为 **`rules.json.bak`**（每次保存覆盖上一次的备份），
> 后悔了直接把它改回 `rules.json` 即可。保存完成后状态栏会显示备份文件名。

两条容易踩的格式约定（编辑器里也是这么处理的）：

| 字段 | 一行一条，**不要**用逗号分隔 |
| --- | --- |
| `content.removeSelectors` | CSS 选择器**本身可以含逗号**（`#content .ad, #content .bottem` 是一条分组选择器），所以只用换行分隔 |
| `headers` | 每行 `Key: Value`，按**第一个**冒号切分（值里常有 `https://` 的冒号） |

### 自带默认规则（开箱即用）

插件**安装后自带一份默认规则**（打包在插件的 `rules-default.json` 里），
内置**天籁小说网 `tlxsbook.com`** 的解析规则。

规则文件不存在时会自动从插件包中写出到上述路径 —— 因此**装完插件无需任何手工配置**，
直接粘贴 `https://www.tlxsbook.com/255_255330/` 这类目录页 URL 就能开始阅读。
触发时机有两处：首次执行「粘贴小说目录URL并阅读」，或在设置页点击
**打开规则文件** / **应用设置**。

> **已有的规则文件不会被覆盖**：只在文件**不存在**时才写出默认规则。
> 你自己的编辑、增删的站点规则都会原样保留。

要在此基础上加站点，直接编辑该文件追加一条 `rules` 即可（可参考文件内已有的注释）。

### 字段说明

顶层结构：`{ "version": 1, "rules": [ ... ] }`。命中规则时把所有 `enabled=true` 且匹配的规则
按文件顺序作为**候选**（最多尝试 3 条，见下「站点改版自愈」）。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ruleName` | string | — | 规则名，仅用于展示 |
| `enabled` | boolean | `true` | 是否启用 |
| `exampleUrl` | string | — | 示例目录页 URL，便于自测 |
| `siteMatch.type` | string | `host` | `host` / `url_contains` / `regex` |
| `siteMatch.pattern` | string | — | 匹配模式 |
| `encoding` | string | `auto` | `auto` / `UTF-8` / `GBK` / `GB2312` |
| `userAgent` | string | 内置浏览器 UA | **站点级 UA 只在这里配**（见下）；留空=内置 UA |
| `headers` | object | `{}` | 附加请求头，如 `{"Referer": "https://..."}`；可覆盖内置头 |
| `toc.containerSelector` | string | `""` | 目录容器 CSS 选择器；留空=整页查找 |
| `toc.linkSelector` | string | — | 章节链接 CSS 选择器，如 `dd a` |
| `content.titleSelector` | string | `""` | 章节标题 CSS 选择器 |
| `content.bodySelector` | string | — | 正文容器 CSS 选择器，如 `#content` |
| `content.removeSelectors` | string[] | `[]` | 正文中要剔除的节点（广告、推荐、分页等） |
| `paging.nextSelector` | string | `""` | 「下一页」链接选择器；优先于文本匹配 |
| `paging.nextTextContains` | string | `下一页` | 按链接文本查找「下一页」 |
| `paging.maxPages` | number | `20` | 多页拼接的最大页数（防站点互链死循环） |

#### 关于 `userAgent`（重要）

**UA 是站点级属性，只能在规则里配，没有全局开关。** 这是刻意的设计：不同站点要求相反 ——
实测 `danfoaaa.com`（品书网）的 WAF **专门拉黑浏览器 UA**（`Mozilla/...Chrome/...` 一律
301 到 `/404.html` 形成死循环），而非浏览器 UA（`novel-reader/1.0`、`curl`）全部放行。
如果有一个全局 UA 开关，用户改完之后某个站点会突然读不了，而**从规则文件上完全看不出原因**。

| 站点类型 | 建议写法 |
| --- | --- |
| 绝大多数站 | 留空 `""`（用内置浏览器 UA） |
| WAF 拉黑浏览器 UA 的站（如 danfoaaa） | 填非浏览器值，如 `"novel-reader/1.0"` |

`headers` 里的键会**覆盖**内置头（内置会发 `Accept`、`Accept-Language`、`Accept-Encoding`、
`Connection`，以及自动维护的 `Referer` 与 `Cookie`），所以需要固定 Referer 的站点直接写
`"headers": { "Referer": "https://example.com/" }` 即可。

### `siteMatch` 匹配方式

- `host`：域名全等或其**子域名**。`example.com` 可匹配 `example.com`、`www.example.com`、`m.example.com`。
- `url_contains`：URL 中包含该子串。
- `regex`：对该完整 URL 做正则查找匹配。

### 选择器语法

**只支持 jsoup 原生 CSS 选择器**（不支持 XPath）：

```text
#content                  id 选择器
.listmain                 class 选择器
dd a                      后代选择器
body > div > dl          直接子元素
a:contains(下一页)         包含指定文本的元素
div#content p            组合
```

### 示例规则

下面是插件自带的默认规则（天籁小说网），可作为新增站点时的模板：

```json
{
  "version": 1,
  "rules": [
    {
      "ruleName": "天籁小说网 tlxsbook.com",
      "enabled": true,
      "exampleUrl": "https://www.tlxsbook.com/255_255330/",
      "siteMatch": { "type": "host", "pattern": "tlxsbook.com" },
      "encoding": "GBK",
      "userAgent": "",
      // 站点额外要求的请求头（可选）。例如某些站必须带本站 Referer：
      // "headers": { "Referer": "https://www.tlxsbook.com/" },
      "headers": {},
      "toc": {
        "containerSelector": "#list dl",
        "linkSelector": "dd a"
      },
      "content": {
        "titleSelector": ".bookname h1",
        "bodySelector": "#content",
        "removeSelectors": [
          "script", "style", "noscript", "iframe",
          "#content .ad", "#content .bottem1", "#content .bottem2"
        ]
      },
      "paging": {
        "nextSelector": "",
        "nextTextContains": "下一页",
        "maxPages": 20
      }
    }
  ]
}
```

> 规则文件支持 **`//` 行注释、`/* */` 块注释**，以及对象/数组结尾的**尾随逗号**，
> 因此可以直接在文件里给自己写备注。字符串里的 `//`（例如 URL）不会被误当成注释。

### 怎么快速填出选择器

1. 在浏览器打开小说目录页，按 `F12`。
2. 右键目录区域 → 检查，找到包裹章节列表的容器（推荐用确定唯一的 `#id` 或 `.class`）。
3. 章节链接一般是容器内的 `dd a` 或 `ul li a`。填入 `containerSelector` / `linkSelector`。
4. 打开任意一章，用同样办法找到正文容器（常见是 `#content`、`#chaptercontent`），填入 `bodySelector`。
5. 若一章分多页，找到「下一页」按钮的链接，填入 `paging.nextSelector`，或保留默认的按文本匹配。

## 设置项

`Settings → Tools → Novel Reader`：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 规则文件（JSON） | `{配置目录}/novelReader/rules.json` | 规则文件路径 |
| 每段最大字数 | `300` | 单条通知展示的最大字数 |
| 请求超时（毫秒） | `10000` | 单次 HTTP 请求超时 |
| 失败重试次数 | `3` | 网络抖动时的额外重试次数（`0` = 不重试） |
| 渲染方式 | `仅通知（默认）` | `仅通知` / `仅专用面板` / `面板 + 通知`；改完**立即生效，无需重启** |
| 正文字号 | `14` | 阅读面板的正文大小（通知走 HTML 字号，不受此项影响） |
| 正文行距 | `1.6` | 阅读面板的行高倍数，范围 `1.0`~`3.0`；面板工具栏上也有 `A±` 与 `↕±` 四个按钮 |
| 离线缓存 | `已开启` | 已读章节不再重复请求、断网也能读（见上文「离线缓存」）；旁边有**「清空缓存」**并显示占用大小 |

> **这里没有 User-Agent 设置**：UA 是站点级属性，只能写在规则文件里（见上文
> 「关于 `userAgent`」）。全局 UA 会让「改一处、某站莫名读不了」且从规则上查不出原因。

### 阅读面板（可选）

`渲染方式` 设为「仅专用面板」或「面板 + 通知」时启用，工具窗在**右侧**，标题 `Novel Reader`。

- **一次显示整章**正文，可自由滚动、可选中复制；**没有**「当前段高亮」，也**不放翻页按钮** ——
  整章都在眼前时，「第几段」不再是需要可视化的位置（理由见下文「关键设计」）
- 顶部工具栏复用现有动作，**每个按钮都有独立图标**，并用分隔线分成四组：
  `上一章 / 下一章` ｜ `章节目录 / 书签列表 / 阅读历史` ｜ `字号± / 行距±` ｜ `关闭阅读`
- **字号与行距**四个调整按钮就在工具栏上，点一下立即生效（到边界时按钮自动变灰）；
  设置页里也有同样两项，可以精确设定
- **状态行**显示当前状态：`正在加载《第 N 章》…`、加载失败的原因、到头提示等 ——
  这是「点了按钮到底有没有反应」的可见依据（提示同时也会进通知留痕）
- 开始或恢复阅读时会**自动弹出**面板（仅在该模式下）；没在读的时候打开它，会显示操作指引

### 网络健壮性（自动，无需配置）

- **重试与退避**：连接超时 / 连接被拒 / 连接重置，以及 HTTP **5xx**、**429** 会按
  `500ms → 1s → 2s → 4s`（封顶 5s，带 ±25% 抖动）退避重试，上限由「失败重试次数」控制；
  **其它 4xx 与「重定向超限」这类站点明确拒绝的情况不重试**，立刻报错让你尽快看到真实原因。
- **站点改版自愈**：命中同一 URL 的规则会按文件顺序全部作为候选（最多试 3 条）。
  旧规则因站点改版「匹配得上但解析不出章节」时，会自动换下一条候选规则重试。

关键设计：

- **菜单收成二级子菜单**：`plugin.xml` 里只在 `ToolsMenu` 下声明一个 `<group>`（父节点），
  各动作统一注册到虚拟分组 `childGroupId="NovelReader.MenuItems"`；
  `NovelReaderActionGroup` 在构造时把该分组下的动作读出来装进自己，于是父节点成为一个
  点开后展开的子菜单。**增删菜单项只改 XML，不动 Java。**
  两个已实测的坑：① `copyFromGroup` 内部会 `setPopup(isPopup(source))`，
  所以必须**先 `copyFromGroup` 再 `setPopup(true)`**，写反了父节点会退化成一个可点击的普通动作；
  ② 收集子动作要用 `getChildren(ActionManager)`，`getChildren(null)` 被平台明令禁止（会打 error 日志）。
- **目录常驻会话**：解析目录后整份章节目录保存在 `ReaderState` 里，并保留命中的
  `NovelRule`，因此后续章节可以在需要时按需抓取，而不必重新输入 URL。
- **游标唯一**：整章一次性切段后只维护一个 `index`；换章由 `ReaderState.applyChapter`
  整体替换内容并把游标复位。所有菜单与快捷键动作都走 `ReaderManager`，不会状态漂移。
- **跨章落点语义**：段内翻页触发的自动续读落在下一章**第 1 段**；往回翻则落在上一章
  **最后一段**（连续阅读不断档）；而「上一章/下一章」这种显式跳章动作一律落在**第 1 段**。
- **章节加载防重入**：抓取章节是后台任务，同一 Project 同时只允许一个在跑
  （`ReaderManager.loading`），连按快捷键不会重复请求；加载期间若用户重新粘贴了目录，
  旧会话的返回结果会被丢弃。
- **通知只装正文**：`ReaderNotifier` 把当前段正文渲染进**标题栏**（HTML 显式压小字号、
  `line-height` 收紧），**内容栏置空串**，且不注册任何 `NotificationAction`。
  章节名与段号一概不出现。之所以能这么写，是因为 `Notification` 的 title/content
  只做 null 校验、不校验空串（实测确认），因此空内容合法，无需零宽字符占位。
- **编码正确**：始终以「字节流 + 显式字符集」交给 jsoup 解析（而非把输入流当字符串读），
  避免 GBK 站点乱码。
- **翻页链接优先级**：先在未清洗的文档上定位「下一页」，再剔除 `removeSelectors`，
  否则规则里常见的「删掉正文区里的翻页链接」会把翻页能力一起删掉。
- **广告需显式声明**：`ContentParser` 只自动清除 `script/style/noscript/iframe`，
  其余（如 `.ad`）必须写进规则的 `content.removeSelectors` 才会被剔除。
- **历史写入只有一个入口**：`ReaderManager.showCurrent()` 渲染后即调用 `saveHistory`。
  因为所有翻页、跳章、目录跳转、从历史恢复的路径最终都经过 `showCurrent`，
  一处写入就覆盖了全部场景，不会出现某条路径漏记（早先分散调用容易漏）。
- **历史用独立 JSON 而非 `@State`**：设置类的小数据走 `@State` XML，
  但历史是**会持续增长的列表**，用独立文件 `history.json` 更合适，也与规则文件的心智模型一致。
  写入用「先写 `.tmp` 再 `ATOMIC_MOVE`（不支持时降级 `REPLACE_EXISTING`）」，避免半截文件。
- **定位用 URL 而不是下标**：目录页改版后章节下标会整体漂移，只有章节 URL 能稳定指向同一章，
  因此 `ReadingHistoryEntry.resolveChapterIndex` 先认 URL、再退回下标并夹取。
- **恢复时重新解析目录**：`SessionOpener.open()` 不信任历史里存的章节列表（可能过期），
  而是按 URL 重新抓目录，用新的下标定位——代价是一次网络请求，换来的是不会跳错章。
- **渲染与状态解耦（`ReaderPresenter`）**：`ReaderManager` 不再直接持有通知渲染器，
  而是把「呈现」交给 `ReaderPresenter`（`present` / `close` / `info` / `error` / `status`），
  默认实现是 `NotificationPresenter`（行为与之前完全一致）。
  这样通知模式下看不出异常、但新增渲染入口忘了走 presenter 的那类 bug 被测试挡住，
  也为「专用阅读面板」留好了位置——加面板时 `ReaderManager` 一行都不用改。
- **历史交互用对话框而不是弹出式列表**：`JBPopupFactory` 的 chooser 弹窗把「整行被点击」
  统一当作「选中并回调」，行内按钮的点击也命中同一个回调 —— 于是「点删除」会连带着
  「打开这本书」。改用 `DialogWrapper` + `JBList` + 按钮后，**列表只负责选择**，
  有副作用的动作一律由按钮显式触发，误触在结构上被消除。
  删除后主动清空选择，防止紧接着回车打开一本错书。
  **所有按钮都从 `createActions()` 返回**（`{继续阅读, 删除选中, 删除全部, 取消}`），
  这样它们才会排在同一个按钮行里；塞进 `createCenterPanel()` 会变成两行。
  数组顺序即按钮顺序，且**最后一个必须是取消动作**（平台按约定绑定 Esc）。
  删除动作是普通 `AbstractAction`（只做事、不关窗），只有「继续阅读」走 `doOKAction()`，
  因此「没选中就不关窗」的校验不会被绕过。
- **章节目录也改成了对话框，并默认定位到当前章**：与历史窗口同一套结构（`DialogWrapper`
  + `JBList` + 单行按钮），顶部多一个筛选框。打开时用
  `selectionPositionFor(可见项下标, 当前章)` 选中当前章并滚动过去
  —— **只选中不滚动等于没定位**（几百章的目录里用户还是看不到自己在哪）。
  这里的滚动有个时序坑：`ensureIndexIsVisible` 依赖 viewport 的真实尺寸，
  而**构造阶段对话框还没布局（列表 0×0），调用它会静默失效**（表现为「选中了但停在开头」）。
  所以首屏滚动统一推迟到窗口显示之后（`override show()` +
  `SwingUtilities.invokeLater`，再叠一层 `componentShown` 兜底）；
  筛选时的重新定位则在列表已可见时直接调用。
- **书签与历史共用同一份「位置还原」逻辑（`util/PositionResolver`）**：
  「URL 优先、下标兜底并夹取」这套规则如果各写一遍，早晚会在「越界怎么夹」这种细节上
  分叉出不一致的行为。现在只有一份实现，历史与书签都委托过去
  （历史的两个方法保留原签名，只是改成一行委托）。
- **书签的 key 用章节 URL 而不是下标**：`tocUrl + (章节URL 或 下标) + 段号`。
  这样「在同一个地方再按一次添加书签」能正确识别为同一位置（不堆重复条目），
  而站点改版后同一位置下标的漂移也不会让新旧书签互相覆盖。
- **书签的备注「非空才覆盖」**：重复添加时用户多半只是想再看看，不是要清掉已写好的备注。
  同理，重复添加不刷新创建时间——保留「第一次标记」的语义。
- **两种顺序刻意分开**：落盘用**创建顺序**（`snapshot()`，文件内容稳定、便于手看手改），
  展示用**阅读顺序**（`forBook()`，按章 → 段排序，跳转列表才符合直觉）。
- **书签只显示当前这本书**：跳转依赖当前会话已解析出的目录，因此不需要网络请求、
  点一下就到；跨书回到某本书由「阅读历史」负责。没有打开的书时会**明确说明**
  而不是静默无反应（区分「一条书签都没有」与「有书签但没打开书」两种情况）。
- **`jumpToPosition` 与 `jumpToChapter` 只差落点**：目标就是当前章时只移动段游标并重绘
  （省一次网络请求）；换章时目标段号**原样传给加载流程**，抓完正文后再由
  `ReaderState.moveToSegment` 夹取 —— 抓取前根本不知道新章有多少段。
- **书签快捷键刻意带 `Shift`**：查过 IDEA 自带 `keymaps/$default.xml`，
  `Ctrl+Alt+B` 是「跳转到实现」、`Ctrl+Alt+M` 是「提取方法」，都是高频键，不去抢占。
  （顺带发现：那个键位表用的是 `control` 全拼，搜 `ctrl` 会全部漏掉。）
- **离线缓存是「缓存优先」而不是「失败才用缓存」**：章节正文是静态内容，重复请求纯属浪费；
  而「网络优先」在断网时要先等超时与重试（默认 3 次）才轮到缓存，读一章等十几秒 ——
  那不叫离线阅读。所以命中缓存就直接返回、一个字节都不请求。代价是站点改了正文不会自动感知，
  用设置页「清空缓存」即可。
- **缓存必须连目录一起存**：只缓存正文是没用的 —— 「从阅读历史恢复」这一步会重新解析目录页，
  没网时直接失败，缓存再多正文也进不去。所以每本书另存一份 `book.json`
  （目录快照 + 书名 + 规则名），目录页打不开时用它把会话建起来，规则留空（正文全从缓存取）。
- **一章一个文件，而不是一本书一个文件**：900 章的书若塞进一个 JSON，每读一章就要重写几 MB，
  既慢又容易在写到一半时把整本书的缓存弄坏。一章一文件每次只写几 KB，坏也只坏一章。
- **缓存条目记着写入时的「每段最大字数」**：分段是在写缓存时就切好的，用户后来改了设置，
  旧缓存的段落划分就和新设置对不上。所以读缓存前比一次参数，不一致就重新抓取（顺带重切）；
  手改的缓存文件没有这个字段（0 = 未知）则直接采信。
- **离线找不到上次那章会就近退让**：历史记的那一章若刚好没缓存，跳到**最近的已缓存章节**
  并说明原因，而不是让整本书都打不开 —— 「缓存了整本却读不进去」是最糟的体验。
- **缓存相关的失败永远不能打断阅读**：读不出来一律视为未命中去联网，写不进去静默忽略；
  连「拿不到缓存服务」（平台未就绪）都返回 null 退化为纯联网行为。
  `ReaderManager.cacheFor` 与 `ChapterCache.getInstanceOrNull` 就是这道防线。
- **面板刻意不做「当前段高亮」，也不放翻页按钮**：面板一次给出整章、由读者自己滚动，
  「读到第几段」就不再是需要可视化的位置概念；高亮块还会随通知模式的翻页键到处跳，只是干扰。
  **但段游标本身照旧**（通知模式、阅读历史、书签都按段定位），面板只是不再把它显示出来。
  整章文本由 `ReaderState.getFullText()` 无损拼接（`PaginationSplitter` 的切分可逆，
  所以不能插入 `\n\n` 之类的分隔符），拼出来就是原文、可以整段复制。
- **行距只能从视图层做**：Swing 里两条看着像的路都是死的（都反编译 JDK 21 确认过）——
  `StyleConstants.setLineSpacing(...)` 设置的值被 `ParagraphView` 存进私有字段后**从不读取**；
  `JTextArea` 的 `PlainView` 行高由 `FontMetrics` 完全决定，没有可覆盖的钩子。
  可行入口是：`ParagraphView` 的行高取自行内子视图的竖直尺寸，于是 `LineSpacingEditorKit`
  用一个把**竖直 span 按倍数放大**的 `LabelView` 顶替默认文本视图（水平方向一点不动，
  否则断行位置会算错）。倍数在布局时现取设置，所以改完只要 `revalidate()` 就生效。
- **所有「点了没反应」的路径都要留下痕迹**：加载开始、被防重入拦下、加载失败、正文应用失败，
  都会写到面板状态行。此前这些只进通知，而通知组是 `displayType=NONE` 不弹窗 ——
  于是「点了下一章什么都没发生」成了唯一观感（这个 bug 就是这么暴露的）。
- **工具窗是懒创建的，所以面板必须能「自拉」**：平台只在用户首次与工具窗交互时才调
  `createToolWindowContent`，而 `present()` 往往在那之前就被调用（刚打开一本书时）。
  因此 `ReadingPanel` 构造时会主动从 `ReaderManager` 拉一次当前状态，
  `PanelPresenter` 则先 `window.show()` 触发创建、再 `invokeLater` 推送 —— 两层保证不白屏。
- **工具栏按钮靠 `DataProvider` 才不会全灰**：现有动作的 `update()` 都依赖
  `event.getProject()`，而 Project 必须由 target component 提供。
  面板实现 `DataProvider`（注意 `getData` 收的是 **String key**，用
  `CommonDataKeys.PROJECT.getName()` 比较）并 `setTargetComponent(this)` 才有 project。
- **工具栏按钮必须各自声明图标，否则它们长得一模一样**：平台在动作没有图标时**不是留空**，
  而是统一套上 `AllIcons.Toolbar.Unknown` 占位图。这种故障**界面上不报任何错** ——
  XML 合法、动作也都能用，只有点开面板才会发现分不清哪个是哪个。
  所以 `ReaderToolbarIconsTest` 把三件事钉死：动作声明了图标、图标文件真实存在且是合法 SVG、
  **图标互不重复**（新增动作时复制粘贴忘了换图标 = 同样分不清）。
  按钮之间还插了分隔线，把「翻一段」和「换一章」这两组最易混的操作隔开。
- **模式分发：`present` 按模式走，`info`/`error` 只走通知，`close` 两个都清**。
  提示类消息在面板里没有消息区，统一走通知才不会同一句话出现两遍；
  而 `close` 两个都清是因为用户可能刚切换过模式，遗留的正文通知仍需清掉（幂等）。
  模式是**每次调用时读设置**的，所以改完立即生效、无需重启。
- **筛选返回的是「真实章节下标」而不是过滤后的位置**：列表显示的是过滤后的可见项，
  而跳转需要真实下标，两者靠一张映射表对应。这是唯一的状态耦合点，错位就会跳错章，
  因此过滤/定位逻辑全部抽成静态方法，由 `ChapterListFilterTest` 覆盖。
  另外，查询是纯数字时**章号正好相等的那一章排最前**（否则搜「50」会先列出 150、250…）。

  跳过 `null` / 空 URL 脏数据、多选取第一个有效项、**删除只删选中的**（其余一本不少）、
  多选删除、脏数据与重复项不连累别人、删除落盘后**重启不复活**、删空后 store 为空

> 在线小说站点大多已失效或不稳定，因此端到端验证主要依赖 `HtmlFetcherMockTest` 中的本地 mock 服务。

## 常见问题

**解析目录失败 / 没有章节**
确认粘贴的是**目录页** URL；检查 `toc.linkSelector` 是否命中（推荐先只用 `#id` / `.class`）。

**正文乱码**
把规则里的 `encoding` 显式写成站点实际编码（如 `GBK`），而不要用 `auto`。

**正文读不全（一章有多个分页）**
检查 `paging.nextSelector` 或 `paging.nextTextContains`。若页面上的翻页文本不是「下一页」，
按实际文本填写（如「翻页」）。

**末页把下一章内容也读进来了**
插件会跳过文本中含「章」的链接；若站点用其他文案，请显式配置 `paging.nextSelector`，
并适当调小 `paging.maxPages`。

**通知不弹出，只出现在 Notifications 列表**
这是默认行为：通知组默认 `displayType="NONE"`（不弹窗），正文只写入 Notifications 面板，
避免阅读时反复弹气泡打断编码。点开右侧 Notifications 面板即可逐段查看。
若希望恢复弹窗，改 `src/main/resources/META-INF/plugin.xml` 里的
`<notificationGroup id="NovelReader" displayType="NONE"/>` 为 `BALLOON`（或 `STICKY_BALLOON`），
或直接改 `Settings → Appearance & Behavior → Notifications` 里 `NovelReader` 的 Popup 级别。

**阅读历史里点某本书，跳到的章节不对**
说明该站点目录改版过。插件已按「章节 URL 优先」定位，通常能自动纠正；
若站点连章节 URL 都换了（例如全站改域名或改 URL 规则），则只能退回按上次的下标定位，
可在历史弹窗里删掉这本书重新开始读。

**想清空阅读历史**
在历史弹窗里点**「删除全部」**（会二次确认），或先多选再点「删除选中」；
也可以直接删除 `{IDEA 配置目录}/novelReader/history.json`（下次打开即为空列表）。

**缓存占多大？怎么清？**
`Settings → Tools → Novel Reader → 离线缓存` 会显示「已缓存 N 本书，占用 X MB」，
旁边就是**「清空缓存」**（二次确认）。清缓存**只删正文缓存**，阅读历史与书签不受影响。
也可以直接删掉 `{IDEA 配置目录}/novelReader/cache` 目录。

**我明明缓存过，站点改版后内容还是旧的？**
这是「缓存优先」的代价：命中缓存就不联网了（否则离线时要先等超时重试才轮到缓存）。
想拿最新内容，清一下缓存再读即可。

**离线时打不开书 / 提示「这一章还没有离线缓存」**
先确认缓存是开着的（设置页）。要真正离线读，需要**目录页也缓存过**——
用「打开：粘贴目录URL阅读」或「阅读历史」成功打开过一次就会自动写下目录快照。
若某一章提示没有缓存，说明它抓取时缓存是关的（或在旧版本下抓的），
联网后用「缓存整本书」补齐即可。

**缓存会不会越攒越大？**
会增长，但一本书通常只有几 MB（900 章约 2～3 MB），且只缓存你读过的章节
（除非手动「缓存整本书」）。目前没有自动清理，设置页能看到占用并一键清空。

**书签窗口里看不到我刚存的书签？**
书签窗口只显示**当前打开的那本书**的书签。若刚重启 IDEA，请先用「阅读历史」恢复那本书，
再打开书签列表。真要清空，直接删 `{IDEA 配置目录}/novelReader/bookmarks.json` 即可。

**为什么加了书签，再在同一个位置加一次没有变成两条？**
这是刻意的：同一个「书 + 章 + 段」视为同一位置，重复添加只更新那一条
（备注非空才覆盖，不会把已写好的备注清掉）。想在同一章里标多个位置，就翻到不同的段再加。

**为什么单章阅读时「添加书签」是灰的？**
单章阅读没有目录页 URL，也就没有「这本书」的标识，重启后无法定位回来 ——
存了只会变成一个跳不过去的死条目。请用「打开：粘贴目录URL阅读」按整本书阅读。

**书签跳到别的章节，内容却不是那一段？**
说明站点改动过正文（段落数变了）。插件会按章 URL 定位到同一章，
段号越界时退到**最后一段**而不是第 1 段，避免进度看起来倒退。

**点删除会不会顺手打开那本书？**
不会。历史窗口里**列表只负责选择**，打开只由「继续阅读」按钮（或双击）触发 ——
这是那次「点 `×` 反而进入阅读」事故后刻意做的结构调整，并已用测试钉死
（`HistorySelectionTest`：没选中时 `pickForOpen` 必须返回 `null`）。

**阅读面板怎么打开 / 怎么换回来？**
`Settings → Tools → Novel Reader → 渲染方式` 选「仅专用面板」或「面板 + 通知」即可，
**改完立即生效、无需重启**。面板在 IDE **右侧**，标题 `Novel Reader`。
想回到原来的通知方式，把「渲染方式」改回「仅通知」。

**面板是空白的 / 没自动弹出来**
- 没在读的时候打开它会显示操作指引，属正常。
- 若正在读却不刷新：确认「渲染方式」不是「仅通知」（那个模式下**不会**碰面板）。
- 面板是**懒创建**的（首次打开才建），插件已做两层兜底（面板构造自拉一次 + 推送时先
  `show()` 再渲染），若仍空白可反馈。

**面板顶部那排按钮是灰的**
不该灰。现有动作的可用性依赖 `target component` 提供的 Project，面板已通过
`DataProvider` 提供（`CommonDataKeys.PROJECT`）。若出现全灰，说明这条链路断了，可反馈。

**点了「下一章」，面板好像没反应？**
先看面板标题下面那行**状态提示**：它会显示「正在加载《第 N 章》…」，加载失败也会在这里
给出原因。若一直停在「正在加载」，多半是站点侧的问题（超时 / 限流 / 规则失效），
提示里的原因就是排查入口。
（面板整章展示，切章会**整屏换掉**；如果你正好停在很相似的一段，看起来会像「没变」。）

**面板里的字太小 / 行太密怎么办？**
工具栏上有四个按钮：`A+` `A-` 调字号，`↕+` `↕-` 调行距，点一下立即生效，到边界会自动变灰。
想精确设定就去 `Settings → Tools → Novel Reader` 里的「正文字号 / 正文行距」。

**用「编辑规则…」保存后，我手写的注释不见了**
这是预期行为：图形化保存会**重写整个文件**，注释与排版无法保留。
原文件已自动备份为 **`rules.json.bak`**，把它的内容改回 `rules.json` 即可还原。
若你重度依赖注释，建议直接用「打开规则文件」手写而不是用编辑器。

**编辑规则保存后，什么时候生效？**
**下次打开一本书（或从历史恢复）时生效**——每次开始阅读都会重新读规则文件。
不需要重启 IDEA，也不用点「重新加载规则」（那个按钮只是校验并报告规则条数）。

**「编辑规则…」提示某条规则「可能有问题」，还能保存吗？**
能。这些提示只覆盖「会导致解析失败」的硬问题（缺 `siteMatch.pattern`、缺 `linkSelector` 或
`bodySelector`、字符集名写错、`maxPages` 非正数）。保存前会汇总给你确认，你选择继续就照存。

## 发布到 JetBrains Marketplace

发布链路已配好，**凭据一律走环境变量、不入库**：

| 环境变量 | 用途 |
| --- | --- |
| `CERTIFICATE_CHAIN` | 插件签名证书链（Marketplace 要求签名） |
| `PRIVATE_KEY` | 签名私钥 |
| `PRIVATE_KEY_PASSWORD` | 私钥口令（无口令可留空） |
| `PUBLISH_TOKEN` | Marketplace 上传令牌 |

```bash
# 本地开发：什么都不用设，照常出包
./gradlew clean buildPlugin          # 产物在 build/distributions/

# 发布：设好上面 4 个变量后
./gradlew signPlugin publishPlugin   # signPlugin 会自动先跑；先发到 default 渠道
```

未设置 `CERTIFICATE_CHAIN` / `PRIVATE_KEY` 时 `signPlugin` 自动跳过；
未设置 `PUBLISH_TOKEN` 时不会配置发布目标。**发到 `default` 渠道后需在 Marketplace 后台手动提级。**

上架前还需：替换 `plugin.xml` 里 `<vendor>` 的**占位 url / email**；
改版本号到 `build.gradle.kts` 的 `version`（唯一维护点）并同步更新 `CHANGELOG.md`。
